## Contratos implementados

```cpp
std::array<corerpg::VisibleFact, 128> storage;
const auto result = corerpg::ContextBuilder::build(authorized_view, {}, storage);
const auto facts = std::span{storage}.first(result.emitted);
// El Host serializa versión, estado y sólo facts. Rechazar o presentar como
// parcial cualquier truncamiento; nunca transmitir la cola de storage.
```

| API | Decisión |
| --- | --- |
| ContextRequest | Versión 1 y filtros AND opcionales por sujeto/tipo; sin texto, ranking o IDs implícitos |
| ContextLimits | Máximos de examen/selección/contenido; capacidad mediante span del caller |
| ContextStatus | Complete, cada truncamiento y rechazos de versión/solicitud/límites |
| ContextResult | Versión efectiva, estado, examinados, emitidos y bytes lógicos; valor escalar |
| ContextBuilder::build | noexcept, sin asignación, scratch dinámico cero, sin acceso al mundo ni RNG |
| FactProvenance / VisibleFact::provenance() | Recuerdo o dato actual concedido al proyectar; igualdad distingue procedencia |

No hay otra API nueva de IA/ejecución. El ejemplo `examples/authorized_context_host.*`
no se instala como contrato del Core: usa una política de Host ilustrativa y
ActionRequest/ActionEngine existentes para contención. No implementa autenticación,
parser de transporte, caducidad, deduplicación, permisos reales ni proveedores.
Esas puertas son obligatorias en producción; ver [frontera IA](../ai-host-boundary.md).

La única modificación a un contrato existente es VisibleFact: el enum privado y
accessor público permiten conservar el origen de la proyección sin inventar fuente
histórica ni aprender grants. Su igualdad incluye procedencia incluso para valores
iguales. Fuente aditiva, firmas existentes intactas; ABI/layout requiere recompilar
consumidores y futuros puentes. No existe ABI estable publicada. Ni KnownFact,
KnowledgeRecord, WorldState ni formatos persistentes cambian.

Los filtros conservan ausencias conocidas (`present=false`). Un hecho no disponible
no se sintetiza. El subconjunto puede omitir existencias autorizadas de extremos:
no es cierre referencial y no autoriza inferir inexistencia por omisión. Tampoco
se autoriza una acción por conocer su ID. Un grant no es recuerdo ni actualidad
perpetua. Copias de vistas/contextos retienen texto sin exponer sus contadores de
ownership; el Host responde de datos enviados previamente y de caches residuales.

## Presupuestos, precedencia y propiedad

| Recurso | Por defecto | Máximo versión 1 |
| --- | ---: | ---: |
| Registros examinados | 4.096 | 65.536 |
| Registros seleccionados | 128 | 256 |
| Contenido lógico | 65.536 bytes | 1.048.576 bytes |
| Capacidad de registros | span del Host | como máximo 256 escritos |
| Scratch dinámico | 0 bytes | 0 bytes, sin parámetro innecesario |

El caller puede reducir los tres presupuestos a cero. No se asigna buffer ni scratch
interno: la memoria auxiliar dinámica tiene límite fijo cero, más estricto que un
presupuesto configurable. La capacidad de almacenamiento de registros es explícita
y configurable por span, no por un segundo buffer interno. La función no conserva
préstamos; el prefijo emitido posee copias con texto inmutable compartido. El caller
mantiene ese almacenamiento hasta acabar de consumirlo y no solapa entrada/salida.
Sólo ese prefijo pertenece a la llamada; la cola queda intacta. No usar la cola
para otra identidad ni serializarla. No mutar entrada/salida concurrentemente.

Preflight: versión → tipo de filtro → máximos. Rechazo devuelve cero contadores y
no escribe. Con sujeto, lower_bound localiza el primer hecho de ese sujeto en
facts(), cuyo orden FactKey agrupa sus registros contiguamente. Sólo se recorre ese
tramo; se detiene antes de examinar el sujeto siguiente. Sin sujeto se mantiene el
recorrido del prefijo de la vista. El filtro por FactKind conserva su AND.

examined cuenta registros visitados para selección antes del filtro por tipo,
sólo del sujeto solicitado cuando lo hay. No cuenta comparaciones de búsqueda
binaria ni hechos de otros sujetos. Oculto/inválido/inexistente sin hechos
autorizados devuelve complete y contadores cero, incluso con límites cero, sin
escribir. Selección: examen → tipo → selección → capacidad → contenido.
Si varias causas coinciden se devuelve la primera en ese orden fijo. Un registro
coincidente bloqueado por salida cuenta como examinado. Si queda otro registro del
tramo candidato tras agotar examen, se indica
examination_limit aunque quizás no quedasen coincidencias del tipo. Terminar
exactamente el tramo dentro del presupuesto permite devolver complete.
Si se agotó salida pero no existe otra coincidencia, el recorrido puede certificar
complete dentro del presupuesto de examen. Vista vacía es completa con límites cero.

Contabilidad lógica por hecho: key (25) + presencia (1) + referencia (8) + total y
latente (16) + procedencia (1) + longitud (8) = **59 bytes**, más bytes de definition_id.
No es un codec nuevo ni `sizeof(VisibleFact)` ni RAM total. No incluye envelope,
STL/allocator, buffers previos o del proveedor, JSON/escaping ni tokens. Se compara
longitud contra presupuesto restante antes de sumar; valores SIZE_MAX se rechazan
por encima de los máximos. No se recorta texto ni se salta silenciosamente un hecho
grandioso para aparentar completitud. Los tokens reales corresponden al adaptador.

## Proyección + selección: análisis y medidas

Sea K el número de recuerdos del observador y G el de grants. Visibility materializa
K registros antes del builder, crea texto actual para definiciones concedidas y
hace búsquedas/inserciones en vector. Sin grants: O(K), más búsqueda del intervalo
de Knowledge O(log N) en la tabla global. Con grants puede mover O(G*(K+G)) registros;
memoria O(K+G) y texto concedido. Duplicados/grants rechazados también cuestan trabajo.
No hay presupuesto de proyección en esta fase: el Host debe acotar entrada/grants
y la escala de Knowledge antes de llamar a esta API privilegiada. No atribuir a
ContextLimits una garantía sobre ese coste ya pagado.

Para N registros de vista y K_s hechos del sujeto, ContextBuilder con sujeto es
O(log N + K_s), acotado a O(log N + min(K_s, max_examined)). Sin sujeto conserva
O(min(N, max_examined)). Copia como máximo
min(capacidad, max_selected) valores, con cero asignaciones y scratch constante.
No recorre caracteres al seleccionar: sólo consulta longitud y comparte texto.
No se promete tiempo real, RAM total del Host ni protección frente a C++ hostil.

Medición reproducible: [tools/measure_context.cpp](../../tools/measure_context.cpp),
compilado `-std=c++20 -O3` contra Core-only Release. Mediana de 51 iteraciones,
hechos de existencia, sin grants/definiciones; setup, destrucción y almacenamiento
externo excluidos. Selección de prefijo con límites por defecto; filtro por último
sujeto examina exactamente un hecho y devuelve complete. Tiempos locales
ilustrativos de la corrección, sin compilaciones concurrentes, no umbrales de
aceptación ni comparación controlada con otro entorno/ejecución.

| K | Proyección μs | Selección prefijo μs | Búsqueda dirigida μs | Sólo registros de vista (bytes) |
| ---: | ---: | ---: | ---: | ---: |
| 128 | 0,351 | 0,390 | 0,030 | 11.264 |
| 4.096 | 10,496 | 0,431 | 0,040 | 360.448 |
| 65.536 | 215,129 | 0,681 | 0,070 | 5.767.168 |
| 65.538 | 210,853 | 0,611 | 0,071 | 5.767.344 |

En esta ABI `sizeof(VisibleFact)=88`; el buffer de 128 registros ocupa 11.264 bytes,
el de 256 ocupa 22.528. No extrapolar a MSVC/ARM64 ni sumar esos bytes lógicos como
si fueran RAM exacta. A 65.536, prefijo examina 129/selecciona 128 y devuelve
selection_limit; búsqueda dirigida examina 1/emite 1 y devuelve complete.
La medida confirma que limitar selección no evita copiar K. No justifica aún una
nueva API compleja de streaming: queda como reevaluación si la integración real
exige acotar proyección, sin afirmar resuelto ese riesgo.
